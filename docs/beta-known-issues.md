# Beta 已知问题

本文记录本轮源码整理后仍未修复、需要共建者确认的行为；不要把它们当成已通过的功能。

- **组队人数边界待修复**：房间协议和 UI 允许 2–4 人，但当前房主席位检查在包含房主后使用 `>=4`，可能拒绝房主＋3名客机的合法四人房间。位置：`apps/desktop/room-service.ts` 的 `hostRoom` admission。
- **客机取消准备待修复**：在 lobby 中，客机点击“取消准备”会进入关闭接收方路径；当前实现可能结束整个 lobby，而不是仅撤销该客机准备。位置：`apps/desktop/party-field-service.ts` 的 `closeRecipient`。
- **野外回营入口待修复**：底部野外场景仍可能显示“回营结算”的街道入口，但该路径发送的命令会被主进程拒绝；实际 field-control 回营对象是另一条路径。位置：`apps/desktop/renderer/overlay.ts` 与 `apps/desktop/shell.ts`。
- **客机配置可信边界待确认**：房主注册共斗时会读取客机发送的 prepared loadout；局域网／已有私网是本 Beta 的信任边界，本地存档可修改，也不提供公共服反作弊。若未来把客机视为不可信，需要把个人准备快照与网络声明做权威比对。

这些问题不影响本轮仓库文档、资源审计和逻辑测试结果；涉及真实两机共斗的验收仍保持阻塞。修复应先补失败测试，再由另一位贡献者复核。
