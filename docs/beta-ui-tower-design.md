# PixelStreet Beta：界面与成就塔设计规格

> **状态：未实现，供共建讨论和后续拆分任务使用。**
> 版本基线：0.19.0 Beta；整理日期：2026-10-31。

这份规格记录本轮希望继续开发的内容。它不代表这些功能已经写入当前 Beta，也不要求贡献者直接把所有内容一次性实现。

## 1. 不变的产品边界

- 地牢之门仍进入原悠游营地；远征之门仍进入原远征整备／挂机。
- 新入口只能增加，不能把旧双门、经营、伙伴、花圃、工坊、背包或旧任务藏起来或改道。
- 底部街道五档高度、原位置和低干扰桌面体验保持不变。
- 不注册全局快捷键，不让动画或测试工具持续抢走用户的键盘焦点。
- 先使用独立试玩档；不读取、覆盖或清理维护者的正式／私人存档。

## 2. 开发者测试档

在 Beta 运行上下文中提供一个明确的“开发者测试”入口：

- 切换到与普通试玩档完全分开的测试档，不覆盖原档；界面持续显示当前为测试档。
- 测试档拥有足够的金币、基础材料、新增怪材、配方、装备和补给，能快速检查商店、背包、野外和成就页面。
- 测试档不能直接把所有成就标记为已完成；必须能测试锁定、进度、领取、失败和重置。
- 提供返回普通试玩档和重置塔测试进度的安全操作；写盘失败不应破坏原档。
- 开发者操作只服务本地测试，不产生联网奖励、交易记录或正式成就统计。

## 3. 双门和窗口交互

### 门的动画

- 地牢门和远征门改为静态表现，不播放持续旋转、循环闪烁或粒子动画。
- 建筑与招牌仍是同一个点击／悬停目标，点击后保留一次性、短时的反馈。
- 停止的是呈现动画，不是经营时钟、挂机结算、门的路由或窗口恢复逻辑。

### 商店焦点

- 商店窗口显示和数据同步完成后，窗口成为当前交互窗口。
- 页面焦点落在安全的首个可操作控件，不自动触发制作、售卖等动作。
- macOS 原生窗口焦点、页面 `document.activeElement`、失焦恢复和关闭行为分别验证。
- 对话输入框的特殊焦点行为不应被普通商店打开逻辑破坏。

## 4. 按钮和建筑点源光

### 按钮

先准备视觉稿，再改运行界面。视觉稿必须使用真正的图像生成工具或维护者提供的精细素材；HTML 截图、SVG、Canvas 或程序绘图不能冒充生成视觉稿。

按钮视觉应融入现有场景，而不是套在背景上的网页控件：

- 普通态使用木牌、石牌、铜牌或布标等有限材质，不把所有按钮做成厚重深青矩形。
- 主操作可以有温暖、克制的亮感；次要按钮安静，禁用态仍然清楚可读。
- 按下是轻微下沉和高光收缩；焦点态必须可访问，但不恢复丑陋的整框泛光。
- 所有按钮仍满足统一手型、禁用原因、可访问名称和至少 44px 的操作目标。

### Hover 光

Hover 不是给建筑或按钮套一个矩形 `outline`／`box-shadow`。光源必须来自建筑自身：

- 地牢门：门灯或门洞产生冷青光，落在门槛和邻近地面。
- 远征门：门楣或火盆产生暖金光，照到门槛与邻墙。
- 商店：窗灯、炉口或晶石灯成为局部点源。
- 光只在 hover、键盘焦点或可领奖状态打开；默认静止，减少动态时保持静态。

验收重点是光的位置和形状：不能看到沿建筑外接矩形一圈发亮。

## 5. 成就之塔与战力

成就之塔应表现成真实的逐层攀登，而不是平铺的成就卡片：

- 纵向塔室、楼梯和落脚点清楚可见，角色站在当前楼层。
- 已完成楼层留下亮灯；后续楼层逐步开放；每次只展开当前层的重要挑战。
- 塔的配色、材质和光照与街道按钮统一，信息文字至少保持可读字号。
- 允许按新规则重新判定试玩档已有成就；正式发布前再确定版本迁移策略。

方向采用“配装驱动的半自动爬塔”：玩家在每层前选择装备、伙伴和补给；战斗中可以点选目标、走位、处理预警。首个实现切片建议先覆盖第 1–4 层，必须是一条完整可玩的路径，不能用“数据已迁移”冒充完整战斗。

### 战力原则

- 显示当前战力、推荐战力和影响来源，来源必须真的影响塔内战斗。
- 战力是成长和准备参考，不是“超过门槛就自动胜利”。
- 破甲、打断、续航／护盾等配装应有不同的实际用途；高战力仍要处理机制，低战力可以靠合理操作弥补。
- 在规格确定前，明确六槽装备、伙伴培养、遗物和补给哪些会进入塔内实战；不能只把没有实际效果的数字加进战力。

### 更有意义的成就

后续成就至少覆盖以下类型，避免靠重复点按钮刷出：

- 指定配装或不同主手完成挑战。
- 处理破甲、打断、首领蓄力和地面预警等战斗机制。
- 限制补给、保持生命／护盾或不额外消耗。
- 连续房间、不同路线或不重复上一层搭配。
- 无伤、首领机制完成、材料和纪念物取得。

每个条件都要有可见进度、失败原因和实际判定；一次性奖励需要幂等，不能重复发放。

## 6. 野外挑战文字

野外挑战页面应按以下顺序显示：

1. 当前挑战和首领状态；
2. 三种材料的当前数量与稳定来源；
3. 制作／配装下一步；
4. 徽记或其他纪念奖励状态；
5. 去远征、背包或塔的明确入口。

文字不能裁切、重叠或依赖颜色单独传达含义；需要在 760×650、1040×720 塔窗口和相关底部高度检查。

## 7. 推荐实施顺序

1. 开发者测试档、静态双门和商店默认焦点。
2. 野外挑战文字布局与塔的基础配色。
3. 生成视觉稿确认后，统一按钮和建筑点源光。
4. 第 1–4 层真实攀塔、战力显示、两类机制挑战、失败返回和逐层领取。
5. 迁移并实战化其余楼层，补齐成就条件、异常退出和最终验收。

每一步都应独立测试；没有图像生成工具时，先保留为规格和待办，不以代码生成图替代设计确认。
