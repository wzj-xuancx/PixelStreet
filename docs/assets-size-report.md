# 资源体积与优化报告

日期：2026-10-31。范围为 0.19.0 Beta 共建源码准备，不是新美术或新玩法交付。

## 为什么原源码 ZIP 有约 247 MB

原始受控清单为 **1,799 个文件、278,934,739 B（266.01 MiB）**，ZIP 后仍约 247 MB，因为大量 PNG 本来就已压缩。体积并非来自 `node_modules`：

| 类别 | 原始字节 | 约 MiB |
|---|---:|---:|
| `assets/` 美术／音频／来源 | 150,417,141 | 143.45 |
| `docs/` 历史图稿与证据 | 98,659,405 | 94.09 |
| `licenses/` 第三方许可 | 20,124,467 | 19.19 |
| `tests/` | 3,437,889 | 3.28 |
| `vendor/` 原始第三方素材 | 3,170,133 | 3.02 |
| `apps/`＋`packages/` | 2,000,785 | 1.91 |

其中 PNG 总计 **243,381,588 B（87.25%）**。没有单个受控文件超过 50 MiB 或 100 MiB。

大背景多为 1536×1024、包含几十万种颜色的插画，不是能直接压成极小色板的 16×16 精灵。最大的单文件其实是 `licenses/LICENSES.chromium.html`，**20,111,209 B**；它是许可，不是图片，随 Electron 二进制分发时必须保留。

## 本轮实际调整

### 1. 不带入历史证据与重复图稿

- 不继承旧 Git 历史，不复制内部验收截图／日志、旧交付回执或全部设计图附件。
- 保留测试真实引用的 `docs/approved-0190/preserved-bottom-baseline.json`，不是整目录盲删。
- 从新导出排除 8 张未运行的概念图、重复源图和失败抠图，共 **17,956,664 B**。
- 原始文件仍在原本地源码归档中；本轮没有删除旧工程或玩家数据。

### 2. 27 张背景转为 WebP q90

- 原始 **90,931,720 B** → **17,040,552 B**，节省约 **81.3%**。
- 单张输出约 **511–780 KB**，保持原分辨率，不裁切或缩放。
- RGB 是有损压缩，**不能称为像素无损**；alpha 逐像素校验保持一致。
- 本轮没有加载图片作人眼对比，也没有真人画面验收；如后续发现局部细节不满意，可按清单从保留的原图重编码。

例子：

| 资源 | 原 PNG | 当前 WebP |
|---|---:|---:|
| `village-0120/village-square` | 3,904,697 B | 779,688 B |
| `camp-060/world` | 3,716,956 B | 717,124 B |
| `expedition-071/glow-trail` | 3,694,323 B | 702,240 B |

### 3. 21 张精灵／装备／物品图集无损 WebP

- 原始 **40,668,342 B** → **30,131,510 B**，节省约 **25.9%**。
- 使用 `lossless=True, exact=True, method=6`，解码后的 **RGBA 逐像素完全相同**，尺寸与裁切坐标不变。
- 部分大图集仍有 1–2 MB。没有为强行达到“几百 KB”而量化颜色、缩小帧或丢弃透明边缘。
- `atlas.png`、13 张 0.19.0 受哈希保护的素材原图、第三方 vendor 原包保留原字节。

### 4. 来源与引用

- renderer 的 CSS、直接图片引用和远征动态文件名已同步为 WebP；原测试中对应扩展名断言同步更新。
- 原 PNG SHA 仍是原始来源的记录；当前文件名、SHA、尺寸、压缩策略和透明度检查以 [`assets/optimization-manifest.json`](../assets/optimization-manifest.json) 为准。
- 15 份来源／说明文件中的个人绝对目录已脱敏，不上传本机用户名和生成目录路径。
- `vendor/` 只有约 3 MB，全部保留，避免打断许可、素材重建或哈希测试。

## 当前效果

`assets/` 从 **150,417,141 B** 降到约 **48,058,028 B（45.83 MiB）**，减少约 **68.1%**。新的源码树预计约 **75 MiB**，含必要测试、第三方原包和完整 Chromium 许可；最终统计以发布前实际清单为准。

不需要为了上传而把整个源码打包成一个 200 MB 文件。GitHub 源码仓库按文件跟踪；App、DMG 和安装 ZIP 适合 Releases，不进普通源码提交。官方限制参考：[About large files on GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。本轮访问官方页面的网络请求失败，因此没有把实时政策抓取记成已完成验证。

## 验证方式

```bash
node scripts/check-repository.mjs
npm run typecheck
npm run build
node --test dist/tests/*.test.cjs
```

资源检查会验证当前优化文件 SHA、静态图片引用与动态远征场景、明显个人路径和超大文件。它不等于人眼美术确认、真实原生 App 首启、物理焦点／IME、跨机网络或全面秘密审计；这些不在本轮伪报通过。
